# Runtime benchmark: zero-GC and frame-time gate

Generated by `npm run bench` (`runtime/test/bench-gc.mjs`) on 2026-11-25, commit `461007f` + this change, runtime 2.2.0, Pixi 8.23.0, Chromium 159.0.8154.6 (headless, software WebGL).

Each run keeps N skill instances casting at once in a virtual loop at 60 or 120 FPS, rendering every frame: 2000 warm-up frames, then 1800 measured frames. Gate: runtime-source allocation and retained heap growth at most 100 B/frame, and no major GC. A stall is a frame over twice the frame budget (33.3 ms at 60 FPS, 16.7 ms at 120 FPS).

Every run also drives one flow trail. Runtime alloc is what V8's sampling heap profiler attributes to `runtime/src`; page alloc includes Pixi's render bookkeeping. Retained growth is the heap after a forced GC, before and after the timed pass. Frame times are CPU time of `vfx.update()` + `app.render()` on a software GL, useful for spotting stalls and regressions, not as phone frame times.
